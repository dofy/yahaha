# 牙花编码规则（Lock Kit）

Lock Kit（`/lock`）为弹子锁生成满足全部限制条件的牙花编码，分**单排**与**双排**两个标签页。逻辑在
`src/lib/lock.ts`，界面在 `src/components/islands/LockKit.tsx`，钥匙模型在
`src/components/islands/KeyProfile.tsx`，回归测试在 `tests/lock.test.ts`。

工具移植自 2017 年的 `phpz/tools/lock`（原始需求文档与 Excel 牙花表保留在该仓库的
`_docs/` 目录）：单排规则来自 `牙花编码程序170619/170626` 与 `明确选项含义`，双排规则来自
`双排牙花编码程序170719`。规则定义沿用原始文档，实现与参数语义按下文重新定义。

## 术语与编码方向

- **弹子号（pin）**：1 到 A。1 号最短、切口最浅；A 号最长、切口最深。
- **弹子孔（chamber）**：1 到 B，自里向外排列。编码第 1 位对应最靠近匙柄的孔。
- **编码（bitting）**：长度为 B 的弹子号序列。A ≤ 9 时按 `123456` 连写，A > 9 时按
  `1-12-3` 用连字符分隔，避免位数歧义。

## 参数

数值参数为 0 表示该条规则关闭。

| 参数 | 含义                   | 规则                                                         |
| ---- | ---------------------- | ------------------------------------------------------------ |
| A    | 弹子个数（牙花号数）   | 可用弹子号为 1..A，上限 20                                   |
| B    | 弹子孔数（编码位数）   | 编码长度，上限 16                                            |
| C    | 必须使用的弹子号       | 未设 E 时，编码中至少出现一次 C                              |
| E    | 使用 C 弹子的弹子孔号  | 设定后，第 E 位必须为 C（此时不再要求其他位出现 C）          |
| D    | 不得使用的弹子号       | 未设 F 时，编码中任何位置都不得出现 D                        |
| F    | 禁用 D 弹子的弹子孔号  | 设定后，仅第 F 位不得为 D                                    |
| G    | 连续相同弹子数         | 最长连续相同弹子段 ≥ G 的编码剔除（G=3 剔除 `122234`）       |
| H    | 相邻弹子号之差         | 任意相邻两位之差的绝对值 ≥ H 的编码剔除（H=5 剔除 `121634`） |
| J    | 相邻相同弹子组数       | 长度 ≥ 2 的相同弹子段数量 ≥ J 的编码剔除（`332244` 为 3 组） |
| K    | 长弹子下限号           | 各位弹子号均 ≤ K 的编码剔除（K=3 剔除 `123123`）             |
| L    | 同一弹子出现次数       | 某一弹子号出现次数 ≥ L 的编码剔除（L=3 剔除 `121231`）       |
| I    | 相异位个数（最小差异） | 两个编码的相异位个数 ≤ I 时只保留其一                        |

两个开关对应原始文档中"可目测剔除"的两条规则，默认开启：

- **剔除全同编码**：`111111` 一类各位相同的编码。
- **剔除阶梯编码**：相邻位差值恒为 +1 或 −1 的编码，如 `123456`、`654321`。

E 必须与 C 同时设置，F 必须与 D 同时设置；I 必须小于 B，否则所有编码互相冲突。
K ≥ A 时没有任何编码能满足"至少一位长于 K"，结果为空。

## 算法

### 枚举与剪枝

搜索按弹子孔从里到外、弹子号从小到大做深度优先遍历，因此输出天然按编码升序排列。
C、D、E、F、G、H、J、L 都是前缀即可判定的条件，一旦前缀违规立即回溯；C（未设 E 时）
与 K 只有完整编码才能判定，但在最后一位上提前判定，等价于剪掉整棵子树。

代价因此与**存活编码数**相关，而不是与 A^B 的全空间相关。A=10、B=16 的全空间是
10^16，仍可在限额内给出前若干个结果。

两个上限保护浏览器主线程，定义在 `src/lib/lock.ts`：

- `DEFAULT_LIMIT`：保留的编码条数上限（结果标记为 `truncated: 'limit'`）。
- `DEFAULT_NODE_BUDGET`：遍历的前缀数量上限（结果标记为 `truncated: 'budget'`）。

### 规则 I 的去重

"相异位个数 ≤ I 即剔除其一"等价于要求保留集合中任意两个编码的汉明距离 > I，即一个
最小距离为 I+1 的码集。实现用掩码哈希代替两两比较：对每个保留的编码，把任意 I 个
位置替换为通配符，生成 C(B, I) 个掩码键存入集合；新编码命中任一掩码键，说明它与某个
已保留编码只在这 I 位上不同，距离 ≤ I，直接丢弃。

两编码距离 ≤ I 当且仅当存在一组 I 个位置覆盖其全部差异，所以掩码命中与距离判定完全
等价，不是近似。单个编码的代价是 C(B, I) 次哈希，而不是与已保留编码数成正比。

因为遍历按升序进行，每一簇相近编码保留的是字典序最小的那个，结果可复现。
C(B, I) 超过 256 时参数校验会要求调低 I。

### 第三方库

查过 `js-combinatorics`、`fast-cartesian`、`cartesian-product-generator`
（只生成笛卡尔积，不能按前缀剪枝，等于"先全枚举再过滤"）、`logic-solver`（MiniSat
的 JS 版）、`kiwi`/`cassowary`（线性约束，不做有限域枚举）以及若干 hamming 距离包
（只比较两个串）。都不覆盖"带前缀剪枝的受限枚举 + 最小距离去重"，因此算法自己实现，
与 `24points.ts` 一样放在 `src/lib/` 并由测试覆盖。

## 钥匙模型

`KeyProfile` 以侧视图画出匙柄与匙身：第 1 孔靠近匙柄，切口越深表示弹子越长。
模型同时标出参数：

- 第 E 孔上方标 `C=<弹子号>`，第 F 孔上方标 `D≠<弹子号>`。
- K 以虚线画在对应深度，保留的编码至少有一个切口落在虚线以下。
- 选中编码后，相邻切口之间标出差值，达到或超过 H 的差值用强调色。
- 悬停或聚焦规则标签时，模型高亮该规则指向的弹子孔；`explainCode` 为每条规则返回
  判定结果、涉及的孔位和说明文字，手工输入的编码也用同一套判定。

## 快捷键

| 键        | 作用                                            |
| --------- | ----------------------------------------------- |
| `1` / `2` | 切换单排 / 双排标签页                           |
| `A`–`L`   | 聚焦该规则的输入框，滚到视口中间并选中内容      |
| `R`       | 执行计算，完成后滚动到钥匙模型                  |
| `V`       | 滚动到钥匙模型                                  |
| `T`       | 回到页面顶部                                    |
| `?`       | 开关快捷键帮助（标签栏右侧的 `?` 按钮同样作用） |
| `Esc`     | 关闭快捷键帮助                                  |

一个字母对应多个输入框时，按该字母循环切换：双排的 A–F 在排 A、排 B 之间切，
H 在 H、H′ 之间切。

约定：

- 焦点在文本输入框（手工试算那一格）或正在输入法组字时，快捷键全部让行；数字输入框
  内仍然生效，因为字母在数字框里没有输入意义。`Esc` 不受此限，任何时候都能关闭帮助。
- 滚动行为遵循 `prefers-reduced-motion`。
- 快捷键帮助是原生 `<dialog>` 弹窗（`showModal()`），焦点陷阱、遮罩、`Esc` 关闭由浏览器
  提供；点遮罩也关。打开前记录当时的焦点元素，关闭后还原，所以从某个输入框打开弹窗再
  关闭，焦点与页面位置都回到原处。

实现见 `LockKit.tsx`：`buildShortcuts` 按表单顺序建立字母到输入框 id 的映射、
`useFieldShortcuts` 处理字母与 `R`、`useGlobalShortcuts` 处理标签页与两个滚动目标
和帮助面板。字母表取自各字段的 `letter`，所以新增参数时不用再登记快捷键；钥匙模型
按 `[data-key-model]` 在当前激活的 tabpanel 里查找。

## 结果列表与预览

- 结果放在固定高度（26rem）的滚动面板里，不再把页面撑长；一次渲染前 600 条，其余走
  CSV。滚动区在 Chrome 下可被键盘聚焦，焦点环按站点 `--color-ring` 着色。
- 双排结果按排 A 分组，组标题（`Row A <编码> · n row B bittings`）粘在滚动区顶部，
  按钮只显示排 B 编码。搜索结果本身就是排 A 升序，所以分组只需相邻合并，不用排序。
- 悬停或聚焦任一结果，`Tooltip` 里用 `KeyProfile` / `KeyProfilePair` 以
  `displayWidth={320}` 画出这把钥匙的实例；双排预览同样带 `sum` 行。
- 点击结果把它送进上方钥匙模型，并在模型不完整可见时滚回模型（`revealModel`
  先判断 `getBoundingClientRect`，已经在视口内就不动）。

## 与 2017 年版本的差异

原始实现（`phpz/statics/js/lock.js`）先构造 A^B 条编码再逐条正则过滤，以下问题在本
次重写中修正：

- 编码生成用 `Math.ceil(i / A^b) % A + 1` 取位，取不出正确的 A 进制位，结果集包含
  重复编码且并非完整空间。
- 编码按字符串处理并用 `\d` 匹配，A > 9 时位数歧义导致规则失效。
- L 的正则 `(\d)(\d?\1){l-1,}` 只能匹配近似相邻的重复，不等于"出现次数"。
- J 的正则要求相同弹子组彼此紧邻，`332244` 之类分散的组数统计不到。
- D 单独设置（未设 F）时被忽略，现按文档语义解释为全局禁用。
- I 用数值偏移在排序后的数组里 `indexOf`/`splice`，既不等价于汉明距离，复杂度也是
  O(n²)；现改为掩码哈希。
- 阶梯编码与全同编码原为硬编码剔除，现为两个可关闭的开关。

导出从 `xlsx` + `FileSaver` 两张工作表（符合条件、不符合条件）改为无依赖的 CSV：
"不符合条件"一侧在大参数下体量可达全空间量级，不再导出；CSV 头部记录本次参数，正文
为序号、编码以及逐孔弹子号。

## 双排弹子（Double row）

双排锁的两排弹子左右并列。每排有独立的 A、B、C、D、E、F；G、H、J、K、L 为两排共用的
限值，但**各排单独判定**；两条规则跨排耦合。界面与数据结构见
`DoubleLockParams`、`solveDoubleLock`、`explainDoubleCode`。

| 参数       | 作用域   | 规则                                                       |
| ---------- | -------- | ---------------------------------------------------------- |
| A、B       | 每排独立 | 例：A 排 a=4、b=6，B 排 a'=3、b'=6                         |
| C、E       | 每排独立 | 语义同单排，E 为该排的孔号                                 |
| D、F       | 每排独立 | 语义同单排                                                 |
| G、J、K、L | 共用限值 | 各排分别判定，任一排违规即剔除该组合                       |
| H          | 共用限值 | 相邻弹子号之差，各排分别判定；双排文档未用，默认 0（关闭） |
| **H′**     | 跨排     | 并排（同一孔号、左右相邻）两弹子号之和 ≥ H′ 的编码剔除     |
| I          | 两排合并 | 两排拼成一条编码后比较相异位个数，例 1-12 位合并考虑       |

孔数不同的两排只有**双方都存在的孔号**构成并排，即前 min(B, B′) 个孔参与 H′ 判定。
H′ 的最小可能和为 2，所以 H′ 只能取 0（关闭）或 ≥ 3。

"全同编码"与"阶梯编码"两个开关按排判定（双排文档只提到全同，阶梯开关默认关闭）。

### 配对算法

每排的规则都是排内条件，所以两排各自跑一次单排搜索，再把存活编码配对，并在配对阶段
判 H′ 与 I：

1. `solveLock(rowParamsFor(params, 0))`、`solveLock(rowParamsFor(params, 1))`，
   其中 `minDistance` 置 0，因为 I 要看合并后的编码。
2. 按 A 排升序、B 排升序两层遍历配对，逐孔检查 `a[i] + b[i] < H′`，首个越界即跳过。
3. 合并成 `[...a, ...b]` 后过同一套掩码哈希距离过滤。

输出顺序因此是"先按 A 排升序、再按 B 排升序"，可复现。三个上限：
`DEFAULT_ROW_LIMIT` 限每排的存活条数（`truncated: 'rows'`）、`DEFAULT_LIMIT` 限配对
结果条数（`'limit'`）、`DEFAULT_NODE_BUDGET` 同时限两次排内搜索与配对比较次数
（`'budget'`）。

配对是 |A 排| × |B 排| 的乘积，规则放得太松时会先撞上配对预算，而且结果会集中在排 A
最小的那些编码上。界面在这种情况下提示收紧规则。实测文档示例（a=4/b=6、a'=3/b'=6、
g=3、h'=6、i=1、j=2、k=2、l=3）：排 A 存活 1,200 条、排 B 存活 66 条，配对后保留
2,808 条，耗时约 28ms。

### 双排钥匙模型

`KeyProfilePair` 把两排画成同一张图：排 A 在上、排 B 在下，共用孔号栅格，中间的
`sum` 行给出每个并排的弹子号之和，达到或超过 H′ 时用强调色。每排各自标注自己的
C=、D≠ 与 K 虚线。规则标签带排别前缀（A/B），悬停时只高亮对应排的孔位；H′ 标签同时
高亮两排。
